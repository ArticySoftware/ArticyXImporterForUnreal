\page databaseView Database View

The **Articy Database** view shows what the importer knows about your project in one place: whether
the import is complete and current, every imported object with its properties, the version of the
plugin and the localization settings.

Open it with **Tools > Articy Utilities > Articy Database**. Like the other articy tabs it can be
docked anywhere in the editor.

![The database view with a filtered object list and the properties of the selected object](database_view.png)

---

### Import State

As long as the import is complete and matches the export, the view only shows the name of the
articy project. Otherwise a help box below the header says what is wrong and offers the import that
fixes it:

| State | Help box | Button |
|---|---|---|
| No export in the articy directory, nothing imported | Tells you where to export to. | - |
| An export that was never imported | Warning | **Import** |
| Generated code or assets are missing | Error | **Full Reimport** |
| Imported with another version of the plugin | Warning | **Full Reimport** |
| The export changed since the last import | Warning | **Import Changes** |

![The help box for an export that was not imported yet](database_view_not_imported.png)

**Import Changes** and **Full Reimport** are also always available in the header, and **Refresh**
reads the state and the objects again. The view refreshes itself when an import finishes.

---

### Objects

The list contains every object of all imported packages with its display name, technical name,
type and id. Click a column to sort by it.

The filter above the list narrows it down to the objects whose name, technical name, type or text
contains what you type. A hexadecimal id like `0x0100000100000C4A` finds the object with that id.

Selecting an object shows its properties on the right, including the properties of its features.
The values are read-only, because the objects are regenerated by every import.

---

### Plugin Updates

The label next to the project name shows the installed version of the plugin, and whether a newer
one was released:

- **Up to date** in green.
- **Update available** as an orange label, if the plugin was installed by hand, e.g. from a GitHub
  release. Clicking it opens the release page.
- **Released on GitHub** as a blue label, if the plugin was installed from **Fab**. Fab releases
  are published after the GitHub release, so the update may not be offered there yet; clicking the
  label opens the plugin on Fab.

![The label for an available update, next to the warning for a changed export](database_view_update.png)

![The label of a plugin installed from Fab, next to the error for an incomplete import](database_view_fab.png)

The view asks GitHub for the latest release once per editor session, when it is opened. Turn this
off with **Check for plugin updates** in **Project Settings > Plugins > Articy X Importer**.

A plugin counts as installed from Fab when it is located in the engine's `Plugins/Marketplace`
folder, which is where the Epic Games Launcher installs it.

---

### Localization

The bar at the bottom shows the language the articy texts are loaded for, which is the language of
the editor. If the project was not exported for that language, the texts of the default language
are used and the bar says so.

Two settings, also found in the project settings, control how texts are looked up:

- **Clear on language switch** (on by default): the texts of the previous language are forgotten
  when the language changes. If turned off, a text that was looked up before is kept for keys the
  new language has no text for.
- **Error on missing text (PIE)** (off by default): a text without an entry in the articy string
  table is reported as an error in the log and in the message log while playing in the editor,
  once per key and language.

**Clear Database** reloads the articy string tables and forgets the kept texts.
